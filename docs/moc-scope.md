# MOC（段階0）でつくる機能

> 段階0は終わり、いまは段階2の機能を実装している（2026-11-14）。この文書は記録として残す。固定データ（`src/server/mocks/`）とデモ用の画面は削除した。

目的は2つ。

1. コーチへのDMで「これなら使いたい」と思ってもらえる見た目と流れを見せる
2. Webブラウザだけで、動画まわり（スロー・コマ送り・線引き）が実用になるかを確かめる

**バックエンドは持たない。** データはすべて `src/server/mocks/` の固定データ。生徒の動画は、端末のファイルを選んでブラウザ内だけで再生する（アップロードしない）。

## 機能の優先度

### 必須（これがないとDMで見せられない）

- 動画プレイヤー：0.25x／0.5x／1x、1コマ送り・戻し、シークバー
- キー位置の指定：コーチが4つの位置で一時停止→「この位置をキャプチャ」
- 線引き：直線、円、矢印、フリーハンド。色2〜3色。元に戻す
- 添削カード：キャプチャ画像＋線＋理由テキスト。カードを並べて1通の返信にする
- 閲覧ページでカードを見る（スマホ前提のレイアウト）
- 受付ページ（スマホ前提）

### あると良い

- チャット（モックデータ＋その場で追加できるだけ）
- 前回の動画との横並び比較
- ドリルの添付（モックの固定ドリルから選ぶ）
- 線引き画像のPNG書き出し（カードのサムネイル用）

### MOCではやらない（段階1以降）

- 骨格推定によるキー位置の自動切り出し（段階1）。MOCでは手で位置を決める。ただし MediaPipe をブラウザで動かせるかの技術検証は MOC 期間中に別ページで試してよい
- 実際のアップロード・保存、ログイン、決済、LINE送信
- ドリル登録、レビュー、受付枠の実際の制御

## 検証したいこと（MOCで答えを出す）

- iPhone Safari で、生徒が撮った縦動画（1080p・60fps）をコマ送りできるか（`requestVideoFrameCallback` と `currentTime` 指定の精度）
- 線引きがスマホ・タブレットの指で快適に使えるか
- 1件の添削カードを作るのに何分かかるか（自分で計測）
