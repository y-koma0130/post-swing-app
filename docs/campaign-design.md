# キャンペーン（手数料の割引）の設計

先行募集の「最初の生徒を受け付けてから3か月は手数料0%」を入れる。この先のキャンペーン（紹介、期間限定の割引など）も同じ仕組みで足せるようにする。
金額や期間はまだ仮の値なので、データや定数で持ち、コードを書き換えずに見直せるようにする。

## いまの手数料

- コーチの手数料は価格の10%（`PURCHASE_RULES.platformFeeRate`、`calcPlatformFee`）。全員同じ
- 生徒は価格に加えてシステム利用料（価格の5%と200円の高いほう。`calcSystemFee`）を払う。全額プラットフォームの取り分
- 単発・お試し、月額の初月：Checkout で仮押さえ → コーチの承認で capture
- 月額の2か月目から：サブスクリプションの請求。手数料は `application_fee_percent`（`calcSubscriptionFeePercent`）
- 支払いの記録は `purchase` の1行だけ。月額の毎月の請求は記録が残らない

## 考え方

- **キャンペーン**（`campaign`）：何を・どれだけ・誰に配るかの定義。「先行募集」など
- **特典**（`coach_fee_grant`）：あるコーチに実際に付いた「この期間は手数料◯%」。付けた時点のキャンペーンの率と日数を写して持つ。あとでキャンペーンを変えても、付いた特典は変わらない

請求のときは**特典だけ**を見て手数料率を決める。キャンペーンの種類が増えても、決済の処理は変えない。

### 「手数料0%」が何を0にするのか

0%にするのは**プラットフォームの手数料（価格の10%）だけ**。
- コーチは**価格の100%**を受け取る。システム利用料は生徒の負担で、コーチの受取額には関係ない
- Stripe の決済手数料、Connect の費用（稼働アカウントの月額、振込の手数料）は、0%の間も**プラットフォームの負担**
- LP・コーチ向け規約には「売上の100%を受け取れます（システム利用料は生徒が負担）」のように、何が0%かをはっきり書く。期間、人数、内容を終了・変更することがある旨も書く
- 将来カード手数料をコーチの負担にする（A案）場合は、この書き方を見直す

## データ

### `campaign`（キャンペーンの定義）

| 列 | 内容 |
|---|---|
| `id` | |
| `code` | `early_adopter_2026` など。固定のキー（一意） |
| `name` | 管理画面に出す名前（「先行募集」） |
| `fee_rate` | 特典の手数料率（0〜0.1。0なら無料） |
| `duration_days` | 特典の日数（90） |
| `anchor` | 特典をいつから数えるか：`first_approval`（初めて申し込みを承認した日）・`granted`（付けた日） |
| `max_grants` | 付与の上限（10）。null なら上限なし。取り消した特典は数えない |
| `active` | 新しく付けられるか（終わったキャンペーンは false にする） |
| `created_at` | |

最初はマイグレーションで行を入れる。管理画面での作成・編集は作らない。

紹介キャンペーンを始めるときに、`trigger`（付与のきっかけ）、紹介した側の特典（`referrer_*`）、受付期間などの列と、`coach_referral` の表を足す。

### `coach_fee_grant`（コーチに付いた特典）

| 列 | 内容 |
|---|---|
| `id` | |
| `coach_user_id` | |
| `campaign_id` | |
| `fee_rate` / `duration_days` | 付けた時点のキャンペーンの値を写す |
| `start_date` / `end_date` | 有効な期間。**日本時間の日付で、両端を含む**（不在期間と同じ）。未開始のあいだは null |
| `revoked_at` | 取り消した日時。行は消さない |

誰が付けた・取り消したかは残さない（管理者は Cloudflare Access の1人だけのため）。
| `created_at` | |

- 同じコーチに同じキャンペーンは1回だけ（`coach_user_id` と `campaign_id` の一意制約。取り消したあとも付け直さない）
- **未開始の特典に期限はない**。承認するまで未開始のまま、枠も使い続ける。動かないコーチは、運営が連絡したうえで取り消して枠を空ける

### `payment`（請求1回ごとの記録）

実際にお金が動いた1回ごとに記録する。キャンペーンがなくても必要な表（月額の2か月目からの請求、問い合わせ、売上の画面）。

| 列 | 内容 |
|---|---|
| `id` | |
| `purchase_id` / `coach_user_id` | |
| `kind` | `capture`（承認での確定）・`invoice`（月額の更新） |
| `price_yen` / `system_fee_yen` | |
| `platform_fee_rate` | 使った手数料率 |
| `platform_fee_yen` | 価格の手数料（システム利用料は含めない） |
| `fee_grant_id` | 使った特典。なければ null |
| `fee_adjusted_yen` | 請求のあとで Application Fee を返金して戻した額（下の「予備」）。なければ0 |
| `refunded_yen` / `refunded_fee_yen` / `refunded_at` | 生徒への返金の額と、そのとき戻した Application Fee。返金がなければ0・null |
| `stripe_payment_intent_id` / `stripe_invoice_id` | 一意。同じ請求を2回記録しない |
| `paid_at` / `created_at` | |

## 手数料率の決め方（domain）

`campaign` の feature を作り、domain に純粋な関数を置く。

```ts
export type ResolveCoachFeeRate = (
  input: Readonly<{ grants: readonly CoachFeeGrant[]; on: LocalDate }>
) => Readonly<{ rate: number; grantId: string | null }>
```

- `on`（日本時間の日付）が `start_date` から `end_date` の間（両端を含む）で、取り消されていない特典の中から、**いちばん低い率を1つだけ**使う。割引は足し合わせない
- 有効な特典がなければ基本の10%。特典の率が基本より高ければ基本の率（特典で上がることはない）
- 手数料の額は、いまと同じく円未満を切り捨て

画面の「2027年2月18日まで」は `end_date` をそのまま出す（両端を含むので、前日にずらす必要はない）。

## 請求のときの流れ

**お金が確定する時点の率を使う**（生徒が申し込んだ時点ではない）。

### 承認したとき（単発・お試し、月額の初月）

1. 承認した日（日本時間）の率を決める。まだ始まっていない特典（`first_approval`）は、その日から始まるものとして扱う。**初めての承認そのものも特典の対象**
2. `paymentIntents.capture` に `application_fee_amount`（価格の手数料＋システム利用料）を渡す。仮押さえのときの額と違っても、capture のときの額が使われる
3. capture が成功したら、未開始の特典を始める（`start_date` = 承認した日、`end_date` = その89日後。90日間）。capture に失敗したら始めない
4. `payment` に記録する

月額は、初月の capture のあとでサブスクリプションを作る。`application_fee_percent` は**作る時点の率**で入れる（特典の期間中なら、システム利用料の分だけの割合）。

### 月額の2か月目から（サブスクリプションの請求）

1. `invoice.created`（請求書が下書きのあいだ。確定の約1時間前）を Webhook で受ける
2. 請求期間の始まりの日の率を決め、`invoices.update` でその請求書の `application_fee_amount` を書き換える
3. `invoice.paid` で `payment` に記録する

### 予備：`invoice.created` が届かなかったとき

Webhook が届かないと、サブスクリプションの `application_fee_percent`（作った時点の率）のまま請求される。0%のはずのコーチから10%取るのは、先行募集の信頼に関わる。

- `invoice.paid` で記録するときに、**正しい率で計算し直す**。実際に取った Application Fee が正しい額より多ければ、Stripe の Application Fee の返金（`applicationFees.createRefund`）で差額を戻し、`fee_adjusted_yen` に残す
- 逆に少なく取っていた場合（特典が終わったのに0%で請求された）は、追加で取らない。コーチに不利な方向には直さない
- 差額を戻した件数と額は、毎日の Cron の集計に出す（ログ）

## 付けるとき・取り消すとき

- **付ける**：管理者がコーチを招待するとき、キャンペーンを選ぶ（任意）。`inviteCoach` のあとで特典を付ける
  - `anchor` が `first_approval`：未開始（期間は null）で付く。付ける前にすでに承認したことがあるコーチなら、付けた日から始める
  - `anchor` が `granted`：付けた日から始める
- **取り消す**：管理画面のコーチの行から。`revoked_at` を入れる。取り消した特典は枠に数えない
- 付けるのも取り消すのも管理者だけ（ユースケースで確認する）

### 上限（10名）を同時に超えないようにする

「数えてから足す」と、同時に付けたときに11人目が入ることがある。
D1（SQLite）は書き込みを1つずつ処理するので、**数える条件を INSERT の中に入れた1つの文**にする。

```sql
INSERT INTO coach_fee_grant (...)
SELECT ... WHERE (
  SELECT count(*) FROM coach_fee_grant
  WHERE campaign_id = ? AND revoked_at IS NULL
) < ?
```

入った行がなければ「上限に達した」として返す。

## 返金のとき

- 返金の処理（`refundThread`）で、`payment` に返金の額と、戻した Application Fee の額を記録する
- 特典の期間はそのまま（返金しても、始まった特典は止めない）

## 先行募集（最初のキャンペーン）

```
code: early_adopter_2026
name: 先行募集
fee_rate: 0
duration_days: 90
anchor: first_approval      # 初めて生徒を承認した日から90日
max_grants: 10
```

- 管理者が招待するときに「先行募集」を選ぶ → 未開始で付く → 初めて生徒を承認した日から90日間、手数料0%（その承認も0%）
- 承認した日から数えるので、始めたらすぐ生徒を集めようという動機になる
- プラットフォームの負担（0%の間）：Stripe の決済手数料（3.6%）、Connect の稼働アカウント（月200円）、振込（0.25%＋250円）。システム利用料でおよそまかなえる
  - 例：月額3,980円の生徒を20人持つコーチ1人の1か月
    - 決済手数料：(3,980＋200)×3.6%×20 ≒ 3,010円
    - Connect の費用：200＋（79,600×0.25%＋250）≒ 650円
    - システム利用料の収入：200円×20 ＝ 4,000円
    - 差し引き：約＋340円
  - 10名・3か月なら、どちらに転んでも小さい額

## 画面

- **管理画面**
  - コーチの招待：キャンペーンを選ぶ欄（任意。残りの枠を出す）
  - コーチの一覧：特典（未開始／◯月◯日まで／終了／取り消し済み）と、取り消すボタン
- **コーチ**
  - 設定の画面：いまの手数料率。未開始なら「最初の生徒を承認した日から90日間、手数料0%」、期間中なら「手数料0%（2027年2月18日まで）」

## 今回は作らないもの

- 紹介（`coach_referral`、紹介した側の特典、紹介の成立で付けるきっかけ）
- 登録したコーチ全員に付くキャンペーン（`coach_signup`）
- 管理画面でキャンペーンを作る・編集する、招待のあとで特典を手動で付ける
- 特典が終わる前のお知らせ
- 生徒向けの割引（クーポンなど）。やるときは「誰が負担するか」を決めて、手数料の特典とは別の表にする

紹介を始めるときに決めること：先行募集の期間中に紹介の特典が付いたら、いちばん低い率だけを使うルールだと紹介の分が実質なくなる。「後ろにつなげる」かどうかを決める。

## feature の分け方

- `src/server/features/campaign/`（新しく作る）
  - domain：`Campaign`・`CoachFeeGrant` の値、`resolveCoachFeeRate`、`calcGrantPeriod`
  - usecases：`grantCampaign`、`revokeGrant`
  - `public.ts`：承認のときの率（未開始の特典も含めて決める）と特典を始める処理、月額の請求のときの率、招待のときの付与、管理画面とコーチの画面の表示
- `purchase`：`capturePurchase`、`invoice.created`（新しく `applyInvoiceFee`）、`invoice.paid`（`recordPayment` で `payment` を記録し、予備の差額を戻す）、`refundThread`（返金を記録）
- `coach`：`inviteCoachAction` でキャンペーンを選べるようにする。設定の画面に手数料を出す

## Stripe の設定

- 本番と staging の「お客様のアカウント」側の Webhook に `invoice.created` を足す

## テスト

- `resolveCoachFeeRate`：特典なし、期間の初日・最終日・翌日（日本時間の境目）、取り消し済み、未開始、重なったときにいちばん低い率、基本より高い率
- 期間：承認した日から90日（`end_date` は89日後）。日本時間の0時前後の承認
- 付与：上限、取り消すと枠が空く、同じキャンペーンを2回、すでに承認済みのコーチは付けた日から、管理者だけ
- 承認：未開始の特典が始まり、その承認も0%。2回目の承認では期間が動かない。capture に失敗したら始まらない
- `invoice.created`：特典の期間中・期間後で `application_fee_amount` が変わる
- `invoice.paid`：多く取っていたら差額を戻して記録する。少なかったら何もしない。同じ請求書を2回受けても1回だけ
- 返金：`payment` に返金の額が残る
